# PAFHub

Стартовый монорепозиторий каталога игр. Клиент собран на React, TypeScript, Mantine и webpack; сервер — на Node.js и TypeScript.

## Структура

```text
client/   React SPA и webpack
server/   HTTP API, схема окружения и интеграционные адаптеры
```

## Запуск

Требуется Node.js 20 или новее.

```bash
npm install
Copy-Item server/.env.example server/.env
npm run dev
```

Клиент работает на `http://localhost:8080`, API — на `http://localhost:3001`. Проверка состояния API: `GET /api/health`.

## Развёртывание на Synology DSM

В корне проекта находятся `docker-compose.yml` и multi-stage `Dockerfile`. Compose собирает production-клиент и API, а Nginx раздаёт SPA и проксирует `/api` к серверу. Для запуска нужны Container Manager с поддержкой Compose и доступ к сборке Docker-образов.

1. Скопируйте проект целиком в `/volume1/docker/pafhub` на NAS. Этот путь указан в bind mounts файла `docker-compose.yml`; при другом расположении замените `/volume1/docker/pafhub` на свой путь.
2. В File Station создайте каталоги `config`, `content`, `client`, `server` и `db` внутри `/volume1/docker/pafhub` (каталоги `client` и `server` уже есть в проекте).
3. Скопируйте `config/.env.example` в `config/.env` и внесите нужные ключи провайдеров.
4. Дайте контейнеру право чтения `config/.env`. API работает от root внутри контейнера, чтобы читать и записывать bind mounts с DSM ACL. Не публикуйте порт API отдельно; наружу опубликован только Nginx на порту `8080`.
5. В Container Manager создайте проект из папки `/volume1/docker/pafhub` и запустите его. Интерфейс будет доступен на `http://<адрес-NAS>:8080`.

При первом запуске API копирует исходные JSON-файлы каталога в `db`, только если соответствующих файлов там ещё нет. После этого `db/games.json`, `db/steam.json`, `db/rawg.json` и `db/f95.json` — постоянные данные; пересборка образов их не перезаписывает. Папка `content` хранит каталоги игр, создаваемые приложением. `client` и `server` монтируются в контейнеры по указанным путям только для чтения как исходники; запущенное приложение собрано в Docker-образах и этими bind mounts не перекрывается.

Для обновления загрузите новые файлы проекта в ту же папку и выполните в Container Manager пересборку/повторный запуск проекта. Для резервной копии сохраняйте папки `db` и `content`, а также `config/.env`.

## Игры и API

Каталог хранится в `db/games.json`. Запросы отправляются обычным JSON; ответы сохраняют используемый сервером формат SuperJSON:

| Метод | Маршрут | Действие |
| --- | --- | --- |
| `GET` | `/api/games?search=&limit=50&offset=0` | Список игр и общее количество |
| `GET` | `/api/games/:id` | Получить игру |
| `POST` | `/api/games` | Создать игру (ID можно не передавать) |
| `PUT` | `/api/games/:id` | Полностью заменить поля игры |
| `PATCH` | `/api/games/:id` | Обновить переданные поля игры |
| `DELETE` | `/api/games/:id` | Удалить игру |

Запись игры имеет поля `id`, `title`, `description`, `version` (строка), `source` (`null` для локальной игры либо объект с `service`: `steam`/`rawg`/`f95` и `id`: ID записи в соответствующем файле источника), `status` (`Completed`/`Uncompleted`/`Played`/`WantPlay`), `folder` (строка) и `online` (boolean). При создании с внешним источником сервер запрашивает его запись и подставляет название, описание и версию; эти поля можно переопределить в форме. Для локальной игры источник указывается как `null` и название вводится вручную. Указанное имя папки создаётся внутри `content/`. Сервер создаёт строковый UUID, если при создании не задан `id`. Путь к файлу можно переопределить через `GAMES_DATA_FILE`.

Для сборки выполните `npm run build`; production-сервер запускается командой `npm start`.

## Импорт Steam

Импортер принимает один или несколько Steam App ID, получает данные из Steam Store API по HTTPS и вставляет или обновляет записи в `db/steam.json`:

```bash
npm --workspace server run import:steam -- 292030
```

Можно задать другой путь через переменную `STEAM_DATA_FILE`. Каждая запись содержит `id`, `link`, полный объект ответа Steam в `raw` и время импорта `importedAt` в ISO 8601.

Хранилище JSON реализовано в `server/src/lib/jsondb.ts`: импортёры держат записи в индексированной по `id` Map, читают файл один раз на пакетный запуск и атомарно сохраняют изменения одним проходом.

## Импорт RAWG и F95

RAWG принимает числовой game ID и требует `RAWG_API_KEY` в `server/.env`:

```bash
npm --workspace server run import:rawg -- 3498
```

Результат добавляется или обновляется в `db/rawg.json`. При необходимости путь можно переопределить через `RAWG_DATA_FILE`.

F95 принимает числовой ID треда. Метаданные треда (название, версия, описание) на F95Zone публичны, поэтому импортёр не требует авторизации: он резолвит канонический URL треда и парсит открывающий пост, добавляя или обновляя `db/f95.json`:

```bash
npm --workspace server run import:f95 -- 123456
```

Путь к файлу можно переопределить через `F95_DATA_FILE`.

## Импорт Epic Games

Публичного списка покупок у Epic Games нет, поэтому импортёр `server/src/importers/epic.ts` обращается к тем же приватным сервисам, что и лаунчер Epic (их используют open-source-лаунчеры Legendary и Heroic). Поддерживаются авторизация по OAuth, список игр аккаунта и метаданные из каталога.

1. Откройте настройки, нажмите **Open Epic login** и войдите в аккаунт Epic в новой вкладке. Страница вернёт JSON с полем `authorizationCode`.
2. Вставьте этот код в поле **Authorization code** и нажмите **Connect Epic account**. Сервер обменяет код на access/refresh-токен и сохранит refresh-токен в `db/settings.json` (наружу клиенту он не отдаётся).
3. Кнопка **Update library** в разделе Epic Games получает список игр аккаунта через `launcher/api/public/assets` и добавляет отсутствующие карточки со статусом `WantPlay`.

Импортировать одну запись вручную можно по паре `namespace:catalogItemId`:

```bash
npm --workspace server run import:epic -- fn:0123456789abcdef0123456789abcdef
```

Запись сохраняется в `db/epic.json` (`id`, `link`, `raw`, `importedAt`); путь можно переопределить через `EPIC_DATA_FILE`. Эндпоинты Epic недокументированы, поэтому интеграция может сломаться после изменений на стороне Epic.

## Обновление библиотеки

Кнопка **Update library** вызывает `POST /api/libraries/:service/update`. Сервер сначала обновляет метаданные игр выбранного сервиса, уже присутствующих в `db/games.json`, а затем получает список игр, которыми владеет пользователь, и добавляет в каталог отсутствующие.

Для Steam список владения берётся из `IPlayerService/GetOwnedGames` (требуются `STEAM_API_KEY` и `STEAM_ID`, а детали игр в профиле должны быть публичными). Каждая новая игра создаётся карточкой со статусом `WantPlay`, для неё подтягиваются полные данные Steam Store, а сырой ответ сохраняется в `db/steam.json`.

Для Epic Games список владения берётся из приватного API лаунчера (`launcher/api/public/assets`); авторизация выполняется в настройках. Идентификатор источника — строка `namespace:catalogItemId`, поэтому импортируются игры с исполняемыми сборками, а контент Unreal Engine пропускается. Метаданные подтягиваются из публичного каталога Epic.

Для RAWG и F95 пользовательского списка покупок не существует, поэтому их импортеры возвращают пустой список и обновляются только уже добавленные игры.

Ответ содержит `updated`, `added`, `total` и `errors`.

## Настройки

Настройки провайдеров (`RAWG_API_KEY`, `STEAM_API_KEY`, `STEAM_ID`, `STEAM_LOGIN`, `STEAM_PASSWORD`, `EPIC_ACCOUNT_ID`) редактируются в интерфейсе через кнопку настроек в верхней панели и сохраняются в `db/settings.json`. API предоставляет `GET /api/settings` и `PUT /api/settings`; путь к файлу можно переопределить через `SETTINGS_DATA_FILE`. Импортёр RAWG использует ключ из настроек, а при его отсутствии — переменную окружения `RAWG_API_KEY`. `STEAM_ID` — 17-значный SteamID64, по которому `Update library` получает список купленных игр; ключ и ID при отсутствии в настройках берутся из переменных окружения `STEAM_API_KEY` и `STEAM_ID`. Ключ должен быть настоящим ключом Steam Web API (32 hex-символа), получить его можно на https://steamcommunity.com/dev/apikey.

Epic Games настраивается не ключом, а OAuth-авторизацией: `EPIC_ACCOUNT_ID` виден в настройках, а `EPIC_REFRESH_TOKEN` хранится в `db/settings.json` и в ответах API не возвращается. Авторизацию обслуживают `GET /api/epic/auth` (ссылка на вход), `POST /api/epic/auth/exchange` (обмен кода) и `DELETE /api/epic/auth` (отключение).

F95Zone настройки не требует: метаданные тредов публичны и импортируются без учётной записи.

## Источники данных

Переменные окружения для Steam и RAWG описаны в `server/.env.example`. Ключи хранятся только на сервере. Внешние клиенты из списка зависимостей изолируются в `server/src/providers`; интеграции Epic и F95 работают без ключей — Epic настраивается в интерфейсе, а F95 импортирует публичные метаданные тредов. Демо-каталог не требует ключей и доступен сразу.

F95Zone защищён Cloudflare: страницы тредов отдаются обычному браузеру, но клиентов с «ботовским» TLS-отпечатком Cloudflare челленджит (`403 Just a moment…`). Импортёр F95 обходит это тем, что запрашивает страницы через подпроцесс `curl` (его TLS-отпечаток Cloudflare пропускает) и повторяет запрос с паузой, если челлендж всё же появится. Для работы требуется `curl` в PATH: в Docker-образ он добавляется через `apk add curl`, на Windows/Linux он обычно уже есть. Интеграция может сломаться после изменений защиты на стороне источника.
